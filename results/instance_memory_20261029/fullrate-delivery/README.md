## 真实消息链路，两个重复

scene-0218 使用原始时间戳，分别输入 40 张关键帧图像与 231 张连续图像；
两边都有 40 帧原始 LiDAR，实时运行 YOLO11n-seg、PTv3、投影关联与语义地图节点。
每次运行独立启动。没有把缓存预测伪装成在线推理。

| 实际输出 | 关键帧图像参考 | 连续图像历史 |
|---|---:|---:|
| 相机范围 point IDF1，两次相同 | 42.9451% | **48.3257%** |
| 相机范围 ID 切换，两次相同 | 32 | 34 |
| 点云发布至实例输出 p95，重复 1 / 2 | 92.67 / 89.37 ms | 93.49 / 93.01 ms |
| 图像节点收到至发布实例包 p95，重复 1 / 2 | 54.88 / 53.83 ms | 54.56 / 51.59 ms |
| 完成图像 / 点云，每次 | 40 / 40 | 231 / 40 |
| 丢帧、超时、待处理积压 | 0 | 0 |
| 最终地图重建一致性 | 通过 | 通过 |

IDF1 提高 **5.3807 个百分点**，并非所有关联指标都改善；切换次数略增。
IDF1/AQ 是本项目明确定义的点身份指标，非官方榜单成绩。
连续模式最大点云延迟为 104.08 / 95.63 ms，初始化为 14.80 / 13.30 s。
每次有 230 个实际收到的实例包带历史，最多 12 条原始记录，证明历史已进入
实际消息，而非仅在离线脚本中存在。历史类别输出仅传输，语义标签改写关闭。
四次运行均保留原始 PTv3 标签，第一帧未关联到及时可用图像，39/40 帧带实例。

这是约 12 Hz 相机、**2 Hz LiDAR**、给定位姿的单片段交付检查。
没有运行 LIVO 前端，不代表 10 Hz 语义 SLAM 或独立场景泛化。
两次重复的身份指标一致；异步链路仍不能代替离线共享检测输出的因果对照。
完整计数、视觉节点事件、模型指纹、地图校验见 [ros-summary.json](ros-summary.json)
及 [ros](ros)。首轮参考组报告的 `scope` 文本误写 full-rate，`fullrate=false`、
40 张图像及实际命令正确；后续重复仅修正文案，未改变预测与调度。

## 原始视觉类别记忆：未通过

固定八个开发日志、1,857 张真实图像、321 帧点云。三组共用同一次 PTv3 输出、
同一组连续图像 ID、相同点组件与当前检测置信度。历史只保存原始 COCO80 分数，
最多 128 个轨迹、每轨 12 条记录、2 秒时限，先读过去再写当前，不反馈融合结果。
融合系数沿用原有 `0.25 × 当前检测置信度`，没有根据结果搜参数。

| 方法 | 全扫描 native16 mIoU | 相机内前景准确率 |
|---|---:|---:|
| 原始 PTv3 | 53.07456% | 84.49071% |

### 适配器一致性与复现限制

八日志中七个身份结果与旧参考精确一致；scene-1074 不一致，camera IDF1
从旧参考 54.9348% 变成 43.5754%。原始预测覆盖相同，轨迹分配发生变化。
单独运行旧跟踪器与新适配器都能重现旧参考；加入 PTv3 同进程环境后出现差异。
隔离 TF32 设置**没有解决**这个问题，不能把它报告成已找到并修好的根因。

随后在 PTv3 交替执行的条件下，固定同一次 YOLO 检测输出，旧代码与新适配器
在所有帧的点划分和最终全部身份指标上完全一致，二者都是 43.5754%。见
[same-forward-adapter-audit.json](visual-precision-isolated/same-forward-adapter-audit.json)。
因此这次检查支持适配器逻辑一致，但独立检测执行的复现限制仍保留。
上述语义三组始终共用当前检测与骨干输出，其失败不依赖于这项跨运行差异。
实际 ROS 的视觉与 PTv3 在独立进程运行。

## 原始点历史：存在答案，但直接投票失败

事先固定只读紧邻上一帧原始预测，25 cm 半径、最多四个邻居、0.75 秒时限。
对照是相同预算的当前帧邻域；票数并列优先保留当前标签。没有历史融合结果反馈。
位姿使用给定 ego 轨迹，未进行物体运动补偿。GT 只在预测后诊断类别与实例对应。

| 方法，同一份原始骨干缓存 | native16 mIoU |
|---|---:|
| 原始 PTv3 | **53.07456%** |
| 当前空间邻域投票 | 52.94550% |
| 上一原始扫描邻域投票 | 52.25746% |

历史投票相对原始预测修正 68,432 点，同时改错 114,676 点；相对当前空间对照
下降 **0.68804 pp**，仅 1/8 日志改善，继续门槛未通过。
特权诊断发现 77,489 个当前错误点具有当前邻域缺少的正确同类/同实例历史答案，
涉及 12 类、8 日志。这是**原始点观测数，不是独立样本数，也不是可部署收益**。
20,833,006 个历史邻接对中，17,036,897 个满足诊断对应规则，错误对应仍可污染投票。
这些结果不支持扩大该投票方案、搜索半径或训练新点记忆网络。

固定参数、原始缓存哈希、逐日志计数和源码见 [point-history](point-history)。
CPU 诊断算子 p95 为 97.93 ms；它包含两种邻域检索，不是线上 GPU 开销。
全部数据来自现有开发日志，冻结骨干用过官方训练数据；本轮不宣称零 3D 标注。

## 复现与保存

精确的语义实验源码快照经过协议 SHA 校验；原始图像、逐点标签和大缓存不上传。
20 项因果、原始写入、时限、消息编码、关联及生命周期测试通过，见 [tests.log](tests.log)。
这些工程检查不替代上面的精度结果。[SHA256SUMS](SHA256SUMS) 覆盖本目录证据。

实际 ROS 运行命令，使用已有 runtime/data 安装，两个命令须顺序执行：

```bash
nice -n 15 taskset -c 12-15 bash tools/visual_instances/run_fullrate_ros_local.sh keyframe /path/to/new-reference
nice -n 15 taskset -c 12-15 bash tools/visual_instances/run_fullrate_ros_local.sh fullrate /path/to/new-fullrate
```

当前启动器另加独占运行锁，避免共享 GPU/ROS 域内的重复启动；不改变算法。
新增语义方法仍不启用，当前可保留的收益来自连续图像给现有跟踪器提供更多因果观测，
不能归因为训练后的 Transformer。
