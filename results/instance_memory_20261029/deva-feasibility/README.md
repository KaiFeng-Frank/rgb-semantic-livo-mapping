# DEVA 在线记忆：真实历史读取成立，多目标成本未通过

**此固定配置停止，不启动完整精度回放、不接入实时节点。** 本轮没有新的语义
或实例精度成绩。测试用已有 scene-0218 开头 32 张图像和缓存的同一次 YOLO
检测；未读取 GT 或新留出集。初次执行及三次重置后的重复均完成，输出精确一致。

## 接入方式与公平对照

[DEVA 官方实现](https://github.com/hkchengrex/Tracking-Anything-with-DEVA)提供外部
检测的在线合并接口。此处固定为 `online`，每帧都提供当前检测；禁用需要后续帧的
缓冲和投票入口。原生模型先传播历史掩码，再匹配/合并当前检测，并写入记忆。
保留原生预测反馈，没有声称满足此前“只保存原始概率”的条件。

当前组使用每帧新建的核心，历史组持续保留核心。两组共享当前图像编码、检测
掩码、类别、分数及相同输出转换。当前组没有持续 ID，**不能作为身份精度的强
基线**；后续若有精度评价，身份比较仍须面对已有全帧率 BoT-SORT。
此处只检查机制和成本。全 128 次调用中，首帧均没有历史读取，其余 124 次均
实际读取一次历史，未来帧缓冲始终为空。

官方默认的 480 短边、64/512/512 通道、10/5 中期记忆帧、10000 长期元素、
128 原型及 top-30 匹配固定。对象一次全部批处理；每次当前检测合并均写入记忆，
没有通过降低检测频率省算力。删除阈值采用自动检测接口的五次未匹配，活动对象
上限 128。实际每帧输入 7–12 个有像素支持的检测，记忆最多同时保留 19 个对象。
这些额外对象可能来自未匹配历史，此处没有 GT 证据判定其正确性。

## 实测成本

本机 RTX 5070 Ti Laptop、CPU 12–15 亲和性、Torch 单线程、FP16、未编译。
运行前 GPU 无其他计算进程。GPU 上完成 RGB 归一化和缩放。
计时为整个适配器调用减去当前对照组的完整计时，包含输入处理、共享编码、
历史读取、匹配、合并、写入、原图尺寸输出及 CPU 结果。
不包含 YOLO、PTv3、文件读取或 ROS。

| 执行 | 第 1–31 帧中位 | p95 | 第 0 帧，另列 |
|---|---:|---:|---:|
| 初次 | 278.04 ms | 319.08 ms | 264.48 ms |
| 重复 1 | 274.90 ms | 308.58 ms | 60.71 ms |
| 重复 2 | 277.21 ms | 315.19 ms | 60.74 ms |
| 重复 3 | 279.55 ms | 314.10 ms | 62.03 ms |

四次均超过预先固定的 **50 ms** 预算。CUDA 峰值 allocated 为 2751.82 MiB；
这与 `nvidia-smi` 包含缓存的进程占用不是同一个统计量。
逐帧值见 [report.json](report.json)，运行前协议位于 [protocol.json](protocol.json)，
提交 `798a29e`。

另做一次同输出的分阶段计时，定位是否值得继续做实现优化。该诊断在阶段边界
同步 GPU，因此不是新一轮部署验收；所有 32 帧的掩码、ID、类别和分数仍与原
输出完全一致。

| 历史路径阶段 | 中位耗时 |
|---|---:|
| 多目标解码 `segment` | 140.96 ms |
| 掩码/状态编码 `encode_mask` | 69.13 ms |
| 记忆匹配 `match_memory` | 36.04 ms |
| 检测匹配与合并 | 9.06 ms |
| 图像编码 | 3.56 ms |
| 记忆写入/压缩 | 1.12 ms |

按每帧实际相加，前两项的中位数为 **209.08 ms**。共享像素匹配并没有使这个
多目标配置达到预算，主要成本在模型内部。因此不继续优化外围小开销，也不
进行分辨率、记忆长度或检测间隔搜索。以上不证明所有视频记忆模型都不可实时。
详见 [分阶段报告](deva-profile-20261029.json)。

## 依赖、保存和限制

源码固定为 `404a112df77f9644d5c7211811329ccd8174b8c3`，未修改官方仓库。
276911801 字节权重从官方发布 API 下载并续传完成，固定 SHA-256：
`5273748214babcbf5bc7aaa23ed4ce5a52f278c974b6c0dafcfbd89fbde25e48`。
发布方未提供 digest，以上是下载后的本地指纹，不能描述为核对了官方 SHA。
载入使用 `weights_only=True` 和严格完整模型键检查。额外 ImageNet 初始化下载
被跳过，所有模型参数由该完整 checkpoint 覆盖。

PuLP 的二进制包下载超时后，采用 [官方 3.3.0 源码](https://github.com/coin-or/pulp/tree/3.3.0)
的纯 Python 部分，固定提交 `348b0052ad2fd9c5261de5403545c9e12c711678`。
它仅满足原生模块的导入依赖，整数规划器未调用。既有 Torch 环境未升级。
原生类别/分数列表及历史 ID 集合仍会增长；本适配器是有限片段的实验实现，
没有完成长期运行节点所需的元数据界限设计。

源码快照、下载记录、全部运行日志、缓存哈希和 [校验结果](validation.json) 已保存。
原始图像、掩码缓存及大权重留在 runtime。基础输入与时序测试见 [tests.log](tests.log)。
这轮排除了一个具体同步候选，既有连续图像跟踪收益和概率记忆的前景损失结论
均保持；完整语义与实例提升目标仍未完成。

后续工作回到已有概率记忆的前景损失诊断，先分清错误对应和错误历史证据各自的
影响，再判断现有在线输入是否足以避免这些伤害。设计优先复用已在运行的
YOLO/PTv3 表征及跟踪 ID；不继续串行叠加完整视频分割模型，也不恢复已失败的
固定概率读出或搜索其混合系数。
