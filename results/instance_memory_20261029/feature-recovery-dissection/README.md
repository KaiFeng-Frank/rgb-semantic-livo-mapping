# 已保存的失去恢复片段：错误进入了哪一层

**两个定点病例把直接触发点定位到历史特征读出：当前输入本来正确，加入历史
特征后翻错；正确候选单独输入也会翻错。训练保护的是旧锚点，选模只按全局
mIoU，这两项都没有直接保护新学会的当前判别能力。**

这不是对所有记忆失败的唯一根因证明。没有重训、重新选检查点或推出新策略。

## 范围与证据对齐

只聚焦前轮保存的 14/18/19 个“同权重开历史后失去恢复”片段，共 51 个
种子—片段记录、27 个不同的场景/对象/时间区间。它们不是 51 个独立场景。
判定来自 [原始训练结果](../feature-supervision-training/README.md)。

已有来源回放覆盖这些相同的片段。130 个对象帧中有 3 个预测正确比例与原提取
略有数值差异，51 个失去恢复的区间，以及全部 52 个“关历史能成功、开历史失败”
的关键对象帧均保持一致，未替换病例。下列点级来源计数来自该来源回放，
不混入原提取的分子分母。完整对齐见 [聚焦报告](focused/report.json) 和
[逐片段记录](focused/cases.json)。

仅为拆开汇总与读出，再选取上述已经保存的两个明确病例作逐层复现。
每个病例使用当帧与紧邻上一帧，共 4 次原始扫描；记忆每次完整替换为上一帧
独立观测，因此没有省略更长的持久融合状态。保留原场景坐标原点与时间戳。
原生/插桩输出和 raw 记忆状态逐值一致，病例中开/关历史的对象正确点数也与
原记录完全一致。没有引入新片段或开展完整精度评测。

## 检索：有局部错配，但它不是这些恢复伤害的主要解释

下表只统计上述关键对象帧里“当前正确、历史改错”的点次。

| 来源证据 | seed 0 | seed 1 | seed 2 |
|---|---:|---:|---:|
| 被改错点次 | 105 | 150 | 156 |
| 全部有效候选都属于正确对象/类别 | 81 | 112 | 126 |
| 至少有一个同对象且类别预测正确的候选 | 0 | 12 | 11 |
| 旧锚点本来错误、当前路径已修对 | 77 | 95 | 103 |

多数伤害发生时，检索已经找对对象。只用 GT 身份过滤候选，只能救回
**2/14、3/18、3/19** 个原失去恢复的片段，支持“关联有局部责任”，不支持
“主要是串 ID，换关联器就能解决”。未知身份没有被计为确定错配。

进一步只保留 GT 同对象、且历史预测类别正确的候选，可以救回
14/14、17/18、18/19 个片段。但必须拆开这个看似很好的数字：在关键帧的
105/139/145 个被修回点次中，**105/138/145 个是候选被清空后退回当前输入**。
这并不证明模型会利用正确历史，更不证明线上能预测 GT 正确性。

## 汇总与读出：定点替换把两者拆开了

病例 A：`scene-0149 / instance 17030 / frame 17 / seed 0`，汽车，11 点。
11 点的有效候选都来自同一汽车，但历史预测错误。病例 B：
`scene-0218 / instance 17019 / frame 39 / seeds 1,2`，汽车，12 点；
原本正确的 11 点各自都有一个同实例、预测为汽车的正确候选。

表内数字是正确点数，所有干预保持同一组权重。

| 固定输入干预 | 病例 A / 11 | 病例 B seed 1 / 12 | 病例 B seed 2 / 12 |
|---|---:|---:|---:|
| 当前 token，关闭历史 | 11 | 11 | 11 |
| 原始历史 | 0 | 0 | 0 |
| 只保留正确历史候选 | 11（清空回退） | 0 | 0 |
| 当前输入只替换历史特征项 | 0 | 0 | 0 |
| 当前输入只替换历史概率项 | 10 | 11 | 11 |
| 当前输入只替换历史几何/年龄/相似度项 | 11 | 11 | 11 |

**病例 B 排除了“必须多个候选混在一起才出错”。** 对那 11 个点，正确候选
各只有一个；独立输入该候选，两个种子仍全部读错。于是这一病例的错误不能
主要归结为检索漏掉正确候选或汇总混坏了候选：正确候选已经到达，单候选读出
仍破坏当前判断。病例 A 则同时存在不可靠历史类别与读出未能抵御的情况。

概率/几何替换没有复现病例 B 的翻错；仅历史特征替换即可复现。这些是冻结
网络的输入干预，可能偏离训练分布，用于定位响应，不是可部署新策略。

具体入口可从现有输入写出。当前输入包含 `[f,f,0,p,0,...]`，历史输入包含
`[f,h,h-f,p,p_h-p,...]`。第一层的历史特征变化为：

\[
\Delta a_{\rm feature}=(W_h+W_{h-f})(h-f).
\]

因此启用历史会同时替换第二份当前特征并加入差分特征，并非在一个冻结的
完整当前判别结果之外添加独立修正。病例 A 的汽车对最强竞争类的 logit
margin 中位数从 **+0.366** 变为 **−1.293**；只替换特征已到 **−1.223**。
第一层表达式由保存的权重和输入直接核验，误差小于 `1.6e-6`。

[保存的候选、汇总向量、逐候选 logits 和检查结果](traces/validation.json)
支持 CPU 独立重算，CPU/GPU logits 最大误差小于 `1e-6`，类别逐项一致。
两例均为汽车；其他片段及行人没有做同样的逐层干预，不能把两例扩大为全体定论。

## 训练目标：保护参照对象落后于当前已学会的能力

[损失实现](../../../tools/semantic_memory/repair_supervision.py)的保留项只在
`anchor.argmax == GT` 时生效，保留的 margin 也来自旧冻结锚点。
它没有把“同权重关闭历史已经正确”作为保护对象。

上述关键帧中 **73.3%、63.3%、66.0%** 的被改错点次属于“锚点错误，但当前
路径已经修对”。病例 A 的全部 11 点、病例 B 原本正确的全部 11 点都属于这一类。
因此现有保留项无法直接表达“不要让历史毁掉这项新学会的能力”。

这不等于它们完全没有监督：CE 和错误修复 margin 仍会惩罚错误。这里证明的是
保护目标的覆盖缺口，以及病例符合该缺口；尚未用受控训练证明它是唯一成因。
分组平衡也基于旧锚点，不等价于给当前反事实已正确的样本提供保护。

## 选模目标：确实允许整体分数与前景取舍，但不能把责任全推给选模

保存的选模代码只按开发 mIoU 选择轮次。已有五轮日志显示：

| 种子 | 选中轮次 | 已保存前景最高的轮次 | 选中模型多得 mIoU，pp | 少得前景准确率，pp |
|---|---:|---:|---:|---:|
| 0 | 5 | 5 | 0 | 0 |
| 1 | 3 | 5 | +0.111 | −0.678 |
| 2 | 5 | 1 | +0.278 | −0.657 |

这是原日志中的目标取舍，不是重新选模的建议或结果。其他轮次没有保存对象
恢复记录，不能宣称换轮次便能修复这些病例；seed 0 甚至不存在此轮次取舍，
仍然发生恢复伤害。最终准入门槛正确拒绝了它，但单一 mIoU 选模本身不能
保护对象恢复。

## 本次判定

- **检索**：有局部责任；多数伤害的对象身份正确，关联修正不足以解决。
- **汇总**：不能解释病例 B；单个正确候选也会失败。其他病例不能据此免责。
- **读出**：两个定点病例中，历史特征通道足以破坏当前正确判别；病例 B
  已确认不是缺少正确候选或必须混合多个候选才出错。
- **训练/选模**：保护旧锚点而未明确保护当前反事实能力；全局 mIoU 选择还会
  接受前景取舍。二者是已定位的目标缺口，尚不是“改完就有效”的结论。

`provenance/` 保留已有来源回放，`focused/` 只取已保存失败片段，`traces/` 是
两个病例的逐层证据。没有扩大实验、重训、打开留出集或修改默认在线输出。
本次交付是定位证据，整体语义与跨帧实例提升目标仍未完成。
