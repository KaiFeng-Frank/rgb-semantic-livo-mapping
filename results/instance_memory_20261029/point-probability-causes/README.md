## 前景损失究竟来自哪里

原概率记忆修正 171 个相机内前景点、改错 278 个，净损失 107 个。

| 原有伤害或过滤影响 | 前景点数 |
|---|---:|
| 所有有效历史邻居已属于同一 GT 类别，仍被改错 | 181 / 278 |
| 所有有效历史邻居已属于同一 GT 实例，仍被改错 | **153 / 278** |
| 类别过滤避免的原有改错 | 93 |
| 实例过滤避免的原有改错 | 120 |
| 实例过滤后剩余改错 | 158 |
| 实例过滤后保留及新增修正 | 163 |
| 实例过滤失去的原有修正 | 14 |

因此，错误对应确实有损失，但 **55.0% 的前景伤害发生在全部邻居实例都正确时**。
实例 ID 一致只说明证据来自同一个对象，不保证历史类别预测正确。
仅删除错误对应不能消除这个问题；这也不证明运动补偿或新的表征一定无用。

两辆卡车贡献了 86 个改错、9 个修正，合计净损失 77 点，约占原前景净损失的
72%。这些点的全部历史邻居已经是正确实例，过滤后损失完全不变：

| 开发场景 / panoptic ID | 前景点观测数 | 改错 / 修正 |
|---|---:|---:|
| scene-0218 / 23033 | 639 | 57 / 9 |
| scene-0420 / 23020 | 656 | 29 / 0 |

全扫描的卡车错误主要混淆到 car；本轮未保存逐点转移，不能据聚合混淆矩阵断言
上述每个目标的每个错误都属于这一路径。共有 182 个带有效 GT ID 的相机前景
目标被统计，不把重复点观测当独立样本。完整对象统计在各场景 JSON 内。

全扫描范围同样有错误证据问题：51,524 个改错中，31,246 个全部邻居已满足
GT 同实例规则（背景只要求同类别）；GT 实例过滤后仍有 35,409 个改错。

## 在线可见量的诊断，不是新门控

在线信号在读取当前 GT 之前算出；GT 仅用于按修正/伤害分组。固定分箱统计
见 [report.json](report.json)。没有用这些结果搜索阈值或调整混合系数。

| 相机前景分组 | 当前置信度均值 | 历史置信度均值 | 历史距离均值 |
|---|---:|---:|---:|
| 被修正的点 | 0.583 | 0.871 | 0.120 m |
| 被改错的点 | 0.684 | 0.820 | 0.144 m |
| 全部邻居同类别、仍改错 | 0.566 | 0.737 | 0.126 m |

两边的历史都比当前更自信，距离也接近。这些均值既不能证明在线不可区分，
也不能证明简单置信度阈值已经足够。后续需要检查现有视觉类别、跟踪质量和
原始跨帧证据能否识别有害历史，不能将“同 ID”直接等价成“可信语义”。

## 校验与下一步边界

6 项相关测试通过，覆盖同实例错误证据、不同类别/实例过滤、无历史回退、未知
实例、有效邻居计数、概率不写回及原有因果时间约束。运行时逐帧断言观察分支
重算的非 GT 概率输出与未修改控制臂完全相同，历史时间严格在当前之前，写入
内容与原始概率一致。独立聚合校验见 [validation.json](validation.json)。

321 帧诊断循环约 52.45 秒，包含重复邻域查询和 GT 统计，**不是部署延迟**。
没有下载新模型、训练新头、改默认在线行为或启动远端实验；没有保存全量概率
缓存或复制原始数据。方案仍关闭。下一步复用现有全帧率跟踪 ID 与 YOLO/PTv3
输入检验可部署关联和证据选择；只有同次前向语义、前景与独立在线成本都过关，
才进入新的留出集。此处不预告它一定成功。
