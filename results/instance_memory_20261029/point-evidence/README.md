这轮把上一轮的 GT 诊断改成真正可在线取得的输入：已有全帧率视觉跟踪 ID、
当前类别分数和原始视觉分数记忆。配置及实现于运行前提交 `31bfd6d`。

## 固定操作与同次前向对照

点云记忆仍为上一原始扫描、四邻点、25 cm、0.75 秒期限、固定 50/50 概率融合。
新操作只有两项：邻居与当前点的可信组件 ID 必须相等（两边未知仍保留，仅一边
未知则拒绝）；如果视觉类别支持当前原始点类别，就否决历史提出的类别改变。
当前视觉和记忆视觉分别做消融。未把 GT、融合输出或校正类别写进记忆。

相机投影只复用既有可信几何组件，没有重新检测或放宽组件规则；321 帧合计
341 个对象观测、16,535 个投影点观测。所有臂共用本次 PTv3 前向和同一视觉缓存。
当前图像融合是已有的固定 `0.25 × detection confidence` 操作，作为必要强对照。
匹配的当前空间组使用同样的 ID 规则和视觉否决，排除查询点自身。

## 为什么 ID 过滤反而损害收益

原历史在相机前景修正 171 点、改错 278 点。加入 ID 规则避免 52 个原有改错，
同时失去 63 个原有修正；最终前景正确数再减少 20。
以下额外审计只检查对应和覆盖，不生成新的语义策略或准确率臂：

| 相机前景覆盖 / 对应 | 数量 |
|---|---:|
| 全部前景点观测 | 38,809 |
| 有可信当前视觉组件 | 16,304 |
| 有四邻域历史 | 24,629 |
| 当前有可信视觉组件且有几何历史 | 10,982 |
| 能读到同一正视觉 ID 的历史 | 7,428 |
| ID 规则拒绝的邻点对 | 20,993 |
| 被拒绝、但 GT 实际同实例的邻点对 | **19,943** |
| 拒绝原因：仅当前侧有 ID | 12,457 |
| 拒绝原因：仅历史侧有 ID | 8,356 |
| 拒绝原因：两边 ID 都存在且不同 | 180 |

约 95.0% 的拒绝对其实属于正确实例；99.1% 的拒绝源于只有一边获得可信投影。
**这暴露了当前规则将“未观测到”当成“不同对象”的设计缺陷，不能解释成跟踪
ID 切换太多。**同正 ID 的 25,938 对中，25,770 对有可评价的双边 GT，全部同实例；
另 168 对 GT 未知，不能算正确或错误。

未知对应应当与确认冲突分开处理。但只修这项仍不是过关证据：视觉否决的支持域
本身不足，下节给出固定操作范围内的数量约束。因此不在本轮结果后追加“把未知
改为保留”的新准确率臂。

## 覆盖区内的完美否决也救不回足够多的前景

原历史的 278 个前景改错中，只有 **49 个**落在当前可信视觉组件内；其中 36 个
视觉类别支持正确的当前原始类别。已有 ID 过滤没有留下可由后续否决改变的输出。

对一个严格限定的操作集合，可以直接计数：保持原历史预测，只允许在当前视觉
覆盖点上选择“保留历史结果”或“回退原始当前结果”。就算 GT 裁判在每一点选对，
最多也只能把原历史的 32,683 个正确点增加到 **32,732 / 38,809**，即 84.34126%。
这仍比原始 PTv3 低 0.14945 pp，比当前图像融合低 0.46639 pp，无法通过前景门槛。

这只是上述有限否决操作的上界，不是跨模态学习、扩大观测支持或其他时空模型的
上界。它说明继续在同一支持域里调否决阈值不会解决当前目标。

上一轮定位的两辆卡车也揭示了不同问题：

| 对象 | 未获当前可信视觉覆盖 | 当前与记忆视觉都判 car | 当前与记忆视觉都判 truck |
|---|---:|---:|---:|
| scene-0218 / 23033，639 点观测 | 565 | 74 | 0 |
| scene-0420 / 23020，656 点观测 | 219 | 0 | 437 |

第一辆有覆盖时两个模态的类别证据仍可能一起错；第二辆的覆盖没有转化为对本轮
有害转移的有效否决。增加相同类别投票次数不能创造缺失证据。

## 成本、验证与后续边界

主候选单独调用计时，含世界坐标转换、视觉缓存展开、单次历史查询、过滤、读出
和 raw 状态写入：中位 **24.87 ms**，p95 **79.42 ms**，最大 122.57 ms。

组件 p95 超过预先规定的 50 ms，不能用中位数或排除初始化来宣布实时过关。

过期/场景重置、原始概率写入、组件重叠及类别元数据检查。逐帧断言候选实际
调用与独立重算相同，聚合与输入哈希校验见 [validation.json](validation.json)。
