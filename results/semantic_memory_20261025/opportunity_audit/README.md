# 联合纠错空间：已有对象预测的事后核查

**评估序列确有当前/历史互补信息，但此前没有在训练前量化这个前提。**
原序列按采集日志哈希选取，目的是避免挑选有利结果；这不能代替对方法适用
条件的检查。本次只读取已保存的预测记录，没有训练、调整阈值、重选序列或
重新提取特征。训练序列上的纠错空间尚未用这份诊断量化。

后续的[完整链路验证](../chain_audit/README.md)已覆盖训练集，并跟踪存储、检索、
正确证据送达和实际修复；也发现并修复了池化随机开关未传播的问题。
本页保留旧缓存上的原始统计，不能与重新提取的数字混用。

## 诊断口径

用同一时序模型、同一组权重，比较“关闭历史”和“开启历史”，避免把两个
独立训练分类头的差别误当历史收益。诊断利用 GT 实例身份确认是否为同一物体；
这些身份仅用于分析，模型本身没有实例跟踪器。

一次观测级机会要求：

1. 当前帧关闭历史时，该物体判断失败。
2. 紧邻上一帧存在同一个 GT 实例，时间差大于零且不超过模型的 0.75 秒期限。
3. 上一帧**原始 B0**对该物体判断成功，符合模型只存原始历史的设定。

成功仍按既有协议定义：至少 5 个被唯一分配给该实例的 GT 语义点，其中至少
一半预测正确。开启历史后，当前帧达到同样条件才记为修复。

计数单位是**物体在一帧中的观测**。同一辆车跨帧会被多次统计，不是独立物体数；
三个种子也不是三倍独立样本。以下不作显著性结论。

## 这些数字能说明什么

观察层面有互补信息，不能用“序列没有纠错空间”解释整体结果。然而这还不能
区分：正确证据是否在存储压缩时丢失、是否被检索到、是否进入查询预算，以及
联合纠错头是否有效利用它。GT 可以确认同一实例，并不意味着模型已经完成关联。

这也不是完整的联合推理上限：即使两帧各自的类别判断都错，特征仍可能互补；
本诊断只统计了一个可明确观测的机会子集。整体 mIoU 和对象事件表现仍沿用
[原始验证记录](../repair_revision/README.md)，不因本次条件统计而改写。

后续定位应沿“原始观测存在正确证据 → 存储保留 → 检索命中 → 进入纠错头 →
修复且未伤害正确判断”逐层检查，并同时报告机会条件下的效果与完整序列的效果。
这些事后找到的高机会场景可用于开发诊断，不能再作为未经查看的独立确认集。
