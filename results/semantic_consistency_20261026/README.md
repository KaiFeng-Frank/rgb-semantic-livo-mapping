# 跨帧语义一致性：真实效果与在线接入

实现了可选的**推理时短时一致性**，并接入在线语义扫描。不是新的训练损失，也不是
完整语义地图上下文网络。保留上一帧原始概率，按已经到达的图修正重新对齐；
输出增强结果不再写回历史，长期回环地图继续融合原始证据。

## 冻结的真实数据评估

六个此前 memory 实验未使用的 nuScenes 官方验证集采集日志，每个日志一场景，
共 **242 帧、8,402,272 点，其中 6,290,255 点有有效评分类别**。选集按日志 token
固定哈希顺序，排除之前 20 场景的全部日志；阈值在这六组推理前冻结，没有根据
结果调整。B0 权重 SHA-256
`35f5d3aec63ae1c383f4a4146e157aa054860cb12b178d899571287e6f97e5f1`。
所有组共享每帧同一次前向的完整概率。

| 方法 | 汇总 native16 mIoU | 相对单帧纠正点数 | 损伤点数 | 同类对应点跳变率 |
|---|---:|---:|---:|---:|
| 单帧原始输出 | 58.0057% | — | — | 4.8779% |
| 同一几何匹配上 0.5/0.5 普通融合 | **58.4552%** | 22,916 | 17,918 | **2.6035%** |
| 条件一致性 | 58.1067% | 4,782 | **2,173** | 4.4405% |
| 条件一致性 + 人为错误历史（压力测试） | 57.9866% | 1,657 | 3,436 | 5.2027% |

条件版本相对单帧 **+0.1011 个百分点、净纠正 2,609 点**。按六个独立采集日志
成组 bootstrap 5,000 次，mIoU 差值 95% 区间 **[+0.0248, +0.1398] pp**。
普通融合相对单帧 +0.4495 pp，区间 [+0.0606, +0.5470] pp。
这里的 mIoU 来自合并混淆矩阵，不是逐场景 mIoU 的平均；不同场景缺失类别不同。

**门控没有全面胜过普通融合。** 它牺牲了不少可纠正点，换来较少的错误覆盖。
全部 1,690,671 个 GT 类别不变的几何对应点对使用相同评估掩码。
连续两帧同样错误的点对计数，单帧为 **76,397**，普通融合 **92,525**，
条件版本 **78,400**。因此条件版本也没有消除“稳定但错误”的现象。

压力测试只循环置换历史静态类别的概率列，保持几何、置信度分布和当前观测不变。
其 mIoU 差值区间 [-0.0380, -0.0043] pp，净损伤 **1,779 点**。
这直接支持“错误上下文会传播错误”的担忧；互为最近邻、概率门控和禁止递归写回
只能限制影响，不能保证历史正确。

物体级首次观测成功数为 133/237，与单帧相同；观察间隔后的重现为 123/224，
单帧 124/224；基线错误恢复成功数均为 147/438。没有物体级全面改善的证据，
尤其不能由静态候选策略推断行人/车辆识别变强。

模块包含输入验证、双向最近邻、门控、混合、历史复制和改类计数，中位
**17.42 ms**、P95 **21.40 ms**、最大 **30.53 ms**。这是该数据流的 CPU 模块
时间，不是端到端延迟。推理包含首次未预热的 802 ms 峰值，不能隐去后称实时。

上表是性能修复后的同数据回归，**不是第二份独立确认集**。首次冻结的结果和源码
保留在 [initial](initial/result.json)：条件版本 +0.1011 pp。随后只把当前帧即可
确定的否决提前到查询之前，并复用重复坐标的正向查询及重复候选的反向查询，
未修改阈值或融合公式。
最终 242 帧逐帧执行全点查询参考，所有输出概率**逐值相等**。由于现有 CUDA 推理
跨进程仍有少量数值变化，前后两次原始指标略有不同；不把这类差异当作改进。

## 完整在线验证

同一本机 RTX 5070 Ti Laptop，HKU1 原始 MCAP 原速 **127.6958 秒**，实时运行
LIVO、PTv3、图优化和语义重融，不读取 GT 位姿、预计算预测或最终离线轨迹。
全部 **1,274/1,274** 初始化后位姿和 **122/122** 个 24,000 点语义关键帧交付。
约 **10 Hz 定位、1 Hz 语义关键帧**；零语义丢弃、零显示覆盖、结束队列排空。

| 最终在线链路 | P95 | 最大值 |
|---|---:|---:|
| 一致性模块自身 | **24.81 ms** | **216.82 ms** |
| 传感器输入至最终位姿接收 | 52.08 ms | 67.53 ms |
| 语义关键帧输入至当前语义扫描接收 | 453.55 ms | 595.82 ms |
| 原始传感器输入至语义地图接收 | 544.25 ms | 673.64 ms |

模块通过预先冻结的 **P95 ≤50 ms** 检查，但 **4/122 帧超过 50 ms**，
不能称为每帧 50 ms 或硬实时。同期关闭一致性的完整对照位姿 P95 53.05 ms。
两个独立 LIVO 运行的图和调度存在差异，不把约 1 ms 的差值解释成定位加速。

第一版对所有点先查对应再做门控，模块 P95 **227.95 ms**，预算失败；
完整原始证据保留在 [initial](initial/online-summary.json)，没有删除失败记录。
短段分阶段计时定位到正反向查询开销；提前否决与复用反向查询把 P95 降到预算内。
中间版本保留在 `early-veto/`。最终还对相同查询坐标复用精确搜索；本段高耗时帧
查询坐标均不同，所以这一步**没有消除全部长尾**，不宣称它解释了主要速度收益。

最终接纳 **19 条**在线回环，完成 **40 次**历史语义重融；107,977 个地图体素
与从原始证据重建的参考逐值一致，最大票重误差 **0**。只保留上一帧的概率历史
峰值 **2,112,128 字节**。一致性实际使用 80,449 次历史对应、改变 7,985 个当前
点标签；HKU1 没有本地语义 GT，**这些改类不能称为纠错**。

独立真实 ROS 用例明确使用人工概率：订阅端收到 `[10,10] → [10,12] → [12,12]`，
验证历史支持、强当前观测推翻历史、图修正重对齐，以及原始地图/历史不被增强
输出覆盖。它不参与准确率或计时。语义回归 199 项通过、1 项跳过、128 个子检查
通过；几何/融合集合 79 项中 2 项无 ROS 检查跳过；原生 19 类 11 项通过。

首次启动时曾把 ROS Python 3.12 的 SciPy 路径全局传入 Python 3.10 几何 worker，
导致启动未就绪，未开始传感器回放；已将可选依赖限定在语义进程环境。日志中的
相机参数服务退出 traceback 是结束后 SIGTERM 引发的 `ExternalShutdownException`，
不发生在传感器交付阶段；没有把此退出噪声隐去后声称全部日志零异常。

## 适用范围

nuScenes 使用原始关键帧和数据集提供的 ego pose 刚性配准，没有逐点去畸变；
这是 16 类源域诊断，不是在线 SLAM 位姿条件的精度验证，更不是 SemanticKITTI19
榜单结果。当前门控排除预测为人车等潜在移动类别的对应；没有目标身份关联、
运动补偿或完整遮挡推理。

默认保持 `--consistency off`，`shadow` 和 `active` 可显式启用。代码与验证基线可用，
不将这组小幅源域收益升级为生产默认或新的方法贡献。下一步若继续增强，应针对
正确/错误历史的可辨识性和物体重现失败，而不是直接加大一致性权重。
